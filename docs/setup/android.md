# Android development setup

TrackWorth's Android app is the same Tauri app built for Android (ADR-0009). The Android project
is generated by `tauri android init` into `src-tauri/gen/android/` and committed. Android-only
config lives in `src-tauri/tauri.android.conf.json`, which sets the package name
**`com.trackworth.app`**. The desktop app keeps `com.trackworth.desktop`.

## One-time setup (macOS)

```sh
brew install --cask android-studio android-commandlinetools temurin@17
rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
```

Install the SDK pieces (Android Studio's SDK Manager works too):

```sh
sdkmanager --sdk_root="$HOME/Library/Android/sdk" "platform-tools" "platforms;android-37.0" \
  "build-tools;37.0.0" "ndk;29.0.14206865" "cmdline-tools;latest"
```

Add this to `~/.zprofile`:

```sh
export JAVA_HOME="$(/usr/libexec/java_home -v 17)"
export ANDROID_HOME="$HOME/Library/Android/sdk"
export NDK_HOME="$ANDROID_HOME/ndk/29.0.14206865"
export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin:$PATH"
```

**Java 17:** Android Studio bundles a newer Java (JBR 25), but the Gradle build is set up for
Java 17.

## Debug signing and Google sign-in

- **Debug key:** debug builds are signed with `~/.android/debug.keystore`, the standard Android
  debug key (alias `androiddebugkey`, password `android`).
- **OAuth client:** the Google Cloud project has an **Android OAuth client** for
  `com.trackworth.app` with this key's SHA-1. Print the SHA-1 with:

  ```sh
  keytool -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey -storepass android | grep SHA1
  ```

- **Other developers' keys:** each developer's debug key has its own SHA-1, which has to be added
  to the same OAuth client.
- **Play:** Play-signed builds need their own clients too (see "OAuth clients" below).

## Release signing (Play upload key)

- **The key:** Play requires a signed **app bundle (AAB)**. It's signed with our **upload key**,
  and Google then re-signs the app for users ("Play App Signing").
- **Where it lives:** outside the repo.
  - `~/.android/trackworth-upload.jks` is the keystore (alias `upload`, RSA 4096).
  - `~/.android/trackworth-upload.properties` holds `storeFile`, `storePassword`, `keyAlias` and
    `keyPassword`.
  - Both are readable only by you (`chmod 600`).
- **Back up both files and the password** in a password manager. A lost upload key can be reset
  through Play support, but that takes days.
- **Build:** `bun run android:release` builds a signed AAB for all architectures into
  `src-tauri/gen/android/app/build/outputs/bundle/universalRelease/`. Without the properties file,
  the release build is left unsigned.
- **CI:** the `android` job in `.github/workflows/release.yml` builds a signed AAB and APK for
  every release and attaches them as `TrackWorth_<version>_android.aab` / `.apk`. It needs two
  repository secrets:
  - `TRACKWORTH_UPLOAD_KEYSTORE_BASE64`: the keystore, base64-encoded
    (`base64 -i ~/.android/trackworth-upload.jks | gh secret set TRACKWORTH_UPLOAD_KEYSTORE_BASE64`);
  - `TRACKWORTH_UPLOAD_STORE_PASSWORD`: its password.

  To build Android for an existing release, run the workflow by hand (Actions → Release → Run
  workflow) with the tag, e.g. `v0.1.0`.

## OAuth clients (one per signing key)

Google matches sign-in by **package name + signing certificate SHA-1**, and an Android OAuth
client holds exactly one SHA-1. The Google Cloud project therefore has one Android client for
`com.trackworth.app` per key the app can be signed with:

| Client name                                           | Key                                                   | Needed for                                    |
| ----------------------------------------------------- | ----------------------------------------------------- | --------------------------------------------- |
| TrackWorth Android (Debug Key)                        | `~/.android/debug.keystore`                           | `bun run android:dev` / `android:build`       |
| TrackWorth Android (Upload Key)                       | upload key `A8:29:7A:33:…:F9:BF`                      | locally signed release builds, the GitHub APK |
| TrackWorth Android (Play Signing Key)                 | Play's current app signing key `B8:30:62:08:…:45:E2`  | Play installs on Android 17+                  |
| TrackWorth Android (Play Signing Key, pre-Android 17) | Play's previous app signing key `4A:EC:DE:59:…:7D:BA` | Play installs on Android 16 and older         |

- **Why two Play keys:** Play ("Protected with Play") moved the app to a hybrid classical +
  post-quantum signing key, which only Android 17 (API 37) and later understand. Older phones
  still see the app signed with the previous key. Play Console lists it under **Protected with
  Play → app signing → Previous app signing keys**; the current key's **classic** SHA-1 is shown
  above it. The post-quantum SHA-1 isn't used for OAuth.
- **Check a real install:** pull the APK and list every certificate it carries:
  `adb shell pm path com.trackworth.app`, `adb pull <path> base.apk`, then
  `apksigner verify --print-certs base.apk`. The `V3.0 Signer` is what phones below Android 17
  use; the `V3.2 Hybrid Classical Signer` is for Android 17+.
- **Symptom of a missing client:** Google's account picker closes right after you pick an account,
  and `adb logcat` shows `UNREGISTERED_ON_API_CONSOLE`. A new client can take a few minutes to
  start working.
- Upload key SHA-1: `keytool -list -v -keystore ~/.android/trackworth-upload.jks -alias upload | grep SHA1`.

## Connecting a phone (no root needed)

1. **Developer options:** on the phone, open Settings → About phone and tap "Build number" 7
   times.
2. **Wireless debugging:** in Developer options, turn on **Wireless debugging**, then tap **Pair
   device with pairing code** and run `adb pair <ip>:<pairing-port> <code>`.
3. **Connect:** run `adb connect <ip>:<port>`, using the port shown on the main Wireless debugging
   screen (it differs from the pairing port, and changes when debugging restarts).
4. **Xiaomi / Redmi / POCO phones:** also turn on **Install via USB** and **USB debugging (Security
   settings)**, otherwise installs fail with `INSTALL_FAILED_USER_RESTRICTED`.

Then run `bun run android:dev` (hot reload), or `bun run android:build` and
`adb install -r src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk`.

## Edge to edge

Android draws apps behind the status and navigation bars. The page uses `viewport-fit=cover`, and
the headers and the bottom menu pad by `env(safe-area-inset-*)`.

## Google sign-in on Android (ADR-0019)

- **Plugin:** our own Tauri plugin `src-tauri/plugins/google-auth`, written in Kotlin, calls Google
  Play services' `AuthorizationClient`. Only the app's Rust auth code calls it. The webview has no
  access, so there are no new UI permissions.
- **First sign-in** shows Google's account picker and consent. After that, tokens come silently
  from Play services.
- **What's stored:** only a `signed-in` flag in the app's data folder, no token.
- **Requirements:** the phone needs Google Play services, and the Android OAuth client must list
  the signing key's SHA-1 (above).
- **Status bar:** `MainActivity.kt` sets white status-bar icons, because the top edge is always
  the logo navy.

## Exports on Android

Export uses our own plugin `src-tauri/plugins/android-files`. It opens Android's "Save to…"
document picker and writes the text to the chosen document, because the save dialog returns a
`content://` address rather than a file path (ADR-0016). Only Rust calls it, so the UI has no
file-system access.
